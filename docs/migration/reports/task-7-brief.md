## Authorization and consent

MCP is an app-user API. A cookie alone, source roster entry, email match or asserted userId never authorizes it. Verify the bearer token with maintained library validation: issuer, exact resource/audience, expiration, current user verification, active session/grant where required, scopes and immediate durable revocation. Resolve the same immutable Better Auth subject/business actor used by UI/API. Test cross-client and wrong-audience tokens, not just obviously invalid strings. Public clients use S256 PKCE; authorization code/client/redirect/resource are bound, single-use and expiry checked. Refresh token rotation/reuse and grant revocation must be tested. A revoked grant must not regain validity when the user later re-consents. Prefer maintained opaque-token introspection if it provides this contract; ordinary JWT signature validation is insufficient and library JWTs cannot be individually revoked. Never claim a stronger revocation guarantee than implemented.

Consent displays authoritative client identity, requested access and precise separate read/write/generate/review capabilities. Treat client metadata as untrusted text; no unvalidated logos, HTML, remote fetches or misleading verified labels. The logged-in user explicitly allows/denies. Validate the signed OAuth request/continuation and exact redirect before leaving the app; never redirect to a query URL just because it was supplied. Login/signup flows must preserve legitimate authorization continuation without weakening existing safe callback checks or account verification. Provide an account-connected-apps view and owner-scoped grant revoke action. Machine-to-machine/platform administration is excluded. Registration and public endpoints require library rate limits/capability restrictions and no skipped consent for arbitrary clients.

The current app global mutation middleware rejects requests lacking exact APP_ORIGIN. Narrow exceptions only for required protocol endpoints: cookie business APIs retain existing CSRF/Origin protections; MCP requires bearer authorization; token/registration/revoke protocol flows rely on maintained client authentication/PKCE and appropriate Origin rules. Cross-origin browser cookie requests cannot gain access through the exception. Discovery paths must reach real handlers before SPA fallback. Handle no-Origin non-browser clients, unsupported methods, protocol negotiation, errors and bounded bodies correctly. Never return HTML for MCP/API failures.
