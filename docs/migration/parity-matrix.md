# Migration parity matrix

This matrix defines the acceptance contract for replacing the Softr application. The acceptance rows describe the required deployed checks; the local execution table below records implementation evidence separately. The five business routes (`/`, `/jobs`, `/job-details?recordId=`, `/profile`, and `/saved-job-details?recordId=`) remain private.

## Evidence baseline

- Repository baseline: `95799ea261871402be2598f5aea3d4109f6065f2`.
- Softr publication metadata: `2026-09-07T05:30:55`; builder update metadata: `2026-09-11T10:07:24`. Softr supplies no timezone for either value, so none is inferred.
- The fresh builder export contains 90 fields and 349 application records: 6 Users, 9 Candidate Profile records, 295 Job Listings, 30 Saved Jobs, and 9 Draft Applications. See the redacted [baseline snapshot](baseline-2026-09-11.json).
- The administrative authentication roster contains six records: one `ACTIVATED` and five `NOT_INVITED`; all six have `active=true` and unique email values that correlate one-to-one with datasource Users. Correlation is not verified identity linking, and `active=true` does not establish that login works.
- All five business page `VIEW` gates are `LOGGED_IN_USERS`. Native `get_block` evidence exposes metadata without action targets, so mutation bindings still require authenticated browser checks.
- The published unauthenticated `/jobs` route redirects to `/login?next-page=/jobs`.
- Relationship checks found zero missing/dangling owners, broken job/draft links, duplicate saves, or archive conflicts. Profile counts per owner are `1,1,1,2,2,2`, confirming the multiple-profile contract.
- All 26 attachment references downloaded: 451499 total reference bytes across six unique files with matching sizes and signatures. A later local ClamAV scan returned no detections for the six unique files. Attachment records remain quarantined; an ongoing deployed quarantine-release process is not configured.
- The initial Cloudflare capture had no sending subdomain. After the user selected `no-reply@auth.lakefrontdev.com`, a refresh at `2026-09-11T14:33:39Z` found that domain enabled with six DNS records ready and no errors. Message previews were disabled on that sender. Capacity is 1,000/day with zero sent; actual staging delivery remains pending. Billing-subscription evidence was unavailable.
- Controlled Softr browser acceptance, native action targets, provider entitlements, deployed target attachment checks, malware scanning, and outbound email delivery remain pending. Two synthetic target users and local attachment migration have separate passing evidence below.

The controller records artifacts in the [evidence manifest](evidence-manifest.md). A row stays pending until that manifest contains the named test result for the exact candidate and environment.

## Release interpretation

`Observed current` describes source evidence only. `Pending` rows are not silently accepted. The five private business routes, owner isolation, fresh-account authentication, attachment reconciliation, ingestion safety, and application MCP readiness or explicit user-approved exclusion are cutover gates. Provider/model assessment may leave generation off without blocking access to migrated legacy drafts.

User scope correction (September 11): account migration is excluded. Fresh target signup replaces source activation and legacy claiming; matching source emails never links private records. Source account-control proofs are archival/native-behavior evidence, not an account-migration release gate.
